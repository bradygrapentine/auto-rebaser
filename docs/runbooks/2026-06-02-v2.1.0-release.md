# Auto Rebaser v2.1.0 — Release & Store Submission

Cut the v2.1.0 release: tag it, build both targets, attach a GitHub release, and submit to the Chrome Web Store + Firefox AMO. Run top-to-bottom; the `Ask:` blocks can be handed to your local Claude Code session, the dashboard steps are yours.

## 1. Prerequisites

- [ ] On `main`, clean tree, fully synced

```bash
cd /Users/bradygrapentine/projects/auto-rebaser && git switch main && git pull --ff-only && git status -s
```

> Ask: "in auto-rebaser, confirm we're on main, the tree is clean, HEAD == origin/main, and main CI is green (gh run list --branch main --limit 1)"

- [ ] Version is already `2.1.0` in both manifests + package.json (bumped in #287)

```bash
grep '"version"' manifest.json manifest.firefox.json package.json
```

- [ ] `gh` authenticated and Chrome/Firefox store accounts accessible

> Note: package.json shows `auto-rebaser@2.1.0`; the live stores are still on 2.0.0 until this runbook completes.

## 2. Tag + GitHub release

- [ ] Create and push the `v2.1.0` tag (mirrors the existing `v2.0.0` tag)

```bash
git tag v2.1.0 && git push origin v2.1.0
```

> Ask: "in auto-rebaser, create the v2.1.0 git tag on main and push it, then confirm `git tag` lists both v2.0.0 and v2.1.0"

- [ ] Build both targets fresh on the tagged commit

```bash
npm run build:all
```

> Ask: "in auto-rebaser run `npm run build:all` and confirm dist/manifest.json and dist-firefox/manifest.json both read version 2.1.0 with no build errors"

- [ ] Zip each target's **contents** (not the parent folder) for upload

```bash
cd dist && zip -r ../auto-rebaser-chrome-2.1.0.zip . && cd ..
cd dist-firefox && zip -r ../auto-rebaser-firefox-2.1.0.zip . && cd ..
```

> Watch: zip the *contents* of `dist/` — if the archive has a top-level `dist/` folder, the store rejects it ("manifest.json not found at root").

- [ ] Publish the GitHub release with notes + both zips attached

```bash
gh release create v2.1.0 \
  --title "v2.1.0 — Needs-you triage, automation filters, smarter rebasing" \
  --notes-file docs/release-notes/v2.1.0.md \
  auto-rebaser-chrome-2.1.0.zip auto-rebaser-firefox-2.1.0.zip
```

> Ask: "in auto-rebaser, create the v2.1.0 GitHub release from docs/release-notes/v2.1.0.md with both store zips attached, and give me the release URL"

[GitHub releases page](https://github.com/bradygrapentine/auto-rebaser/releases)

## 3. Chrome Web Store submission

- [ ] Open the developer console → Auto Rebaser

[Chrome Web Store developer console](https://chrome.google.com/webstore/devconsole)

- [ ] Upload `auto-rebaser-chrome-2.1.0.zip` as a new package
- [ ] Paste the v2.1.0 "what's new" / changelog from the release notes

```bash
cat docs/release-notes/v2.1.0.md
```

- [ ] Confirm no new permissions are requested (v2.1.0 adds none — `notifications` stays optional/runtime)
- [ ] Submit for review

[Live Chrome listing](https://chromewebstore.google.com/detail/auto-rebaser/fcbanfgcfcjmhnoanachedlpbopiodpi)

> Watch: a new permission in the manifest triggers a slower "permission review" + can disable the extension for existing users until they re-accept. v2.1.0 should show **no** permission delta — verify before submitting.

## 4. Firefox AMO submission

[Firefox Add-on Developer Hub](https://addons.mozilla.org/developers/)

- [ ] Upload `auto-rebaser-firefox-2.1.0.zip`
- [ ] If prompted for source code (Vite minifies the bundle), upload the repo source + build instructions: `npm ci && TARGET=firefox vite build`, output in `dist-firefox/`

- [ ] Submit for review

> Watch: AMO's automated validator flags minified/bundled code and asks for reviewable source. Have the repo zip + the `TARGET=firefox vite build` instruction ready so the human review isn't blocked.
